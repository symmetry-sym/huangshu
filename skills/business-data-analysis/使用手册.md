# 商业数据分析（business-data-analysis）使用手册

> 从自己的经营数据中发现问题、验证判断，并得到下一步行动。

**适用对象：** 小红书创作者、电商经营者、企业老板、运营负责人、数据分析人员  
**适用任务：** 分析小红书笔记数据、分析抖老板订单数据、检查经营趋势、制作数据报告、搭建本地数据采集  
**支持文件：** JSON、CSV 及字段结构兼容的经营数据导出  
**版本：** V1.0｜2026-09-06

---

## 1. business-data-analysis 是什么

`business-data-analysis` 是一个面向自有经营数据的分析 Skill，主要完成两类任务：

1. **分析已有数据：** 读取你提供的 JSON 或 CSV 文件，检查数据质量，计算经营指标，识别趋势并形成行动建议。
2. **协助本地采集：** 在你明确要求时，配置本地采集服务，帮助你从自己有权访问的小红书创作者后台或抖老板订单页面导出数据。

默认优先分析你已经提供的文件。除非你明确提出“帮我采集”，否则它不会启动采集服务，也不会操作浏览器。

它不只是做统计表，还会区分：

- 数据能够直接证明的**观察**；
- 仍需进一步验证的**假设**；
- 当前最值得执行的**优先动作**；
- 下一轮分析最应该补充的**数据**。

## 2. 30 秒快速开始

最短调用方式：

```text
使用 business-data-analysis，分析这个数据文件：【文件路径】。
这是【平台与数据类型】，我想了解【经营问题】。
请先检查数据质量，再输出核心指标、趋势、异常、结论和下一步行动。
```

小红书示例：

```text
使用 business-data-analysis，分析这份小红书笔记数据：【CSV 文件路径】。
我想知道最近 90 天哪些选题最容易获得阅读、互动和涨粉。
请先检查缺失值、重复数据和异常值，再按内容类型、主题和发布时间分析，
最后给出未来 30 天的内容调整建议。
```

订单示例：

```text
使用 business-data-analysis，分析这份抖老板订单导出：【JSON 文件路径】。
请分析订单量、文件中已有的收入字段、商品集中度、订单状态、退款取消和时间趋势，
并明确说明每个金额字段的原始含义，不要自行推测 GMV 或净收入。
```

## 3. 推荐任务模板

复制下面的模板，按实际情况填写：

```yaml
使用 business-data-analysis：

数据来源：

数据类型：
希望分析的时间范围：
最想回答的问题：
重点指标：
需要的交付物：
需要隐藏的信息：
其他限制：
```

### 每一项怎么写

| 字段 | 建议写法 | 示例 |
|---|---|---|
| 数据来源 | 写清平台和后台类型 | 小红书创作者中心 |
| 文件路径 | 提供本地 JSON/CSV 的完整路径 | `/项目/data/xhs-notes.csv` |
| 数据类型 | 笔记、订单或其他经营导出 | 小红书笔记表现数据 |
| 时间范围 | 写具体日期或最近多少天 | 2026-06-01 至 2026-08-31 |
| 最想回答的问题 | 只设 1–3 个核心问题 | 什么内容能带来有效涨粉？ |
| 重点指标 | 优先写文件里确实存在的字段 | 曝光、阅读、互动、涨粉 |
| 需要的交付物 | 报告、表格、图表或行动清单 | Markdown 报告＋Excel 分析表 |
| 需要隐藏的信息 | 姓名、手机号、订单号等 | 隐藏客户姓名和订单编号 |
| 其他限制 | 不合并的口径、禁止推断的字段等 | 不把下单金额当作实收金额 |

如果你不确定数据里有哪些字段，可以只提供文件并说明业务问题。它会先识别字段，再告诉你哪些指标能算、哪些不能算。

## 4. 支持哪些数据

### 小红书创作者笔记数据

优先分析：

- 曝光量；
- 阅读或播放量；
- 封面点击率；
- 点赞、收藏、评论、分享等互动；
- 平均观看时长；
- 涨粉数；
- 内容类型与选题；
- 发布时间与发布频率。

### 抖老板订单数据

优先分析：

- 订单数量；
- 导出文件中已有的收入或金额字段；
- 商品、客户或渠道集中度；
- 订单状态分布；
- 日、周、月时间趋势；
- 退款、取消或售后情况；
- 平台导出中存在的其他业务维度。

### 其他经营数据

如果 CSV 或 JSON 的结构与上述经营数据相近，也可以尝试分析。系统会先识别字段与单位，再决定能够安全计算的指标。

它不会为缺失字段编造定义。例如文件只有“订单金额”，但没有说明它是下单金额、支付金额还是结算收入，报告会保留原字段名称并明确口径未知。

## 5. 它会怎样工作

```text
识别文件与业务类型
    ↓
检查字段、行数和日期范围
    ↓
检查缺失、重复、单位与异常值
    ↓
确认能够安全计算的指标
    ↓
分析趋势、分组与集中度
    ↓
区分观察与假设
    ↓
输出结论、优先行动和下一批数据建议
```

### 数据质量检查

正式计算前，通常会检查：

- 总行数与有效记录数；
- 最早、最晚日期以及日期是否连续；
- 关键字段是否缺失；
- 是否存在重复笔记、重复订单或重复编号；
- 数字单位是否一致；
- 极端大值、负数、零值或明显异常记录；
- 统计口径是否能够从字段名称中确认。

重要限制会写进报告。数据质量不足时，它会先说明“能得出什么”和“不能得出什么”，不会用精确数字掩盖口径问题。

## 6. 小红书分析重点

### 常见指标

| 指标 | 作用 | 注意事项 |
|---|---|---|
| 曝光量 | 判断平台分发规模 | 曝光高不等于用户真正阅读 |
| 阅读/播放量 | 判断内容被消费的程度 | 需区分图文与视频口径 |
| 封面点击率 | 判断标题与封面的吸引力 | 只有分母有效时才计算 |
| 互动量 | 判断内容是否引发反馈 | 点赞、收藏、评论的价值不同 |
| 平均观看时长 | 判断视频留存与内容节奏 | 需结合视频时长理解 |
| 涨粉数 | 判断内容对账号长期价值 | 不等于直接成交 |
| 内容类型/主题 | 找到稳定有效的内容方向 | 需要统一分类标签 |
| 发布时间 | 判断时间段与表现是否有关 | 相关不等于因果 |

### 常见推导指标

当所需字段存在且分母大于 0 时，可以计算：

```text
封面点击率 = 阅读或播放量 ÷ 曝光量
互动率 = 互动量 ÷ 阅读或播放量
涨粉转化率 = 涨粉数 ÷ 阅读或播放量
```

这些属于推导指标，报告中会明确标注计算方式。不同平台页面可能采用不同官方口径，不会把自算指标冒充平台官方指标。

### 常见分析问题

- 哪些主题曝光不高，但点击率和涨粉效率高？
- 哪些内容曝光很高，却没有带来互动或关注？
- 图文和视频分别擅长带来什么结果？
- 收藏高、评论高、涨粉高的内容有什么差异？
- 发布时间与内容表现是否存在稳定关系？
- 最近 30 天的表现变化来自内容、频率还是单篇爆款？

## 7. 订单数据分析重点

### 常见分析维度

| 维度 | 可以回答的问题 |
|---|---|
| 订单量趋势 | 订单是在增长、下降，还是被少数日期拉高？ |
| 金额趋势 | 文件中已有的金额字段如何随时间变化？ |
| 商品集中度 | 收入或订单是否过度依赖少数商品？ |
| 客户集中度 | 是否过度依赖少数客户？ |
| 状态分布 | 待付款、已支付、已完成、已取消分别占多少？ |
| 退款与取消 | 哪些商品、日期或渠道更容易产生退款取消？ |
| 周期变化 | 工作日、周末、月份或活动期是否存在差异？ |

### 金额口径原则

订单导出中的“订单金额”“支付金额”“优惠后金额”“结算金额”“退款金额”可能代表不同业务含义。

分析时会：

1. 保留原始字段名称；
2. 只计算文件中确实存在的金额；
3. 对口径不清的字段标记“待确认”；
4. 不自行把某个金额定义成 GMV、营收、实收或利润；
5. 在有退款字段时，明确说明是否计算了扣除退款后的结果。

## 8. 常见任务怎么提

### 做一次经营体检

```text
使用 business-data-analysis，对这份经营数据做完整体检：【文件路径】。
请先检查数据质量，再总结规模、趋势、结构、异常、风险和增长机会，
最后给出按优先级排序的 5 个行动建议。
```

### 找出小红书高价值选题

```text
分析这份小红书数据，找出最值得持续做的选题。
不要只按曝光排序，请同时考虑点击、收藏、评论、涨粉和平均观看时长。
把“数据观察”和“选题假设”分开，并给出下一轮内容测试计划。
```

### 复盘最近 30 天

```text
分析【文件路径】最近 30 天与前 30 天的变化。
请比较发布量、曝光、阅读、互动和涨粉，指出变化主要来自整体改善、
内容结构变化还是少数爆款，并列出需要进一步验证的原因。
```

### 分析订单与商品结构

```text
使用 business-data-analysis 分析这份订单数据：【文件路径】。
请按商品统计订单数和文件中已有的金额字段，分析商品集中度、状态分布、
退款取消与时间趋势，最后给出应该重点保留、观察和调整的商品。
```

### 检查客户集中风险

```text
分析订单数据中的客户集中度。
请计算前 1、前 5、前 10 名客户的订单和金额占比，
但在报告中隐藏姓名、联系方式和订单编号。
```

### 生成 Excel 分析表

```text
使用 business-data-analysis 分析这份 CSV，并生成一个可编辑的 Excel 工作簿。
请包含：原始数据检查、核心指标、时间趋势、内容/商品分组、异常记录和行动建议。
```

### 生成汇报文档

```text
把分析结果整理成一份适合给老板看的经营复盘报告。
先写结论，再放关键指标和图表；区分确定事实、合理假设和待补数据。
```

## 9. 完整示例：小红书内容复盘

```yaml
使用 business-data-analysis：

数据来源：小红书创作者中心
文件路径：/项目/data/xhs-notes-2026Q3.csv
数据类型：笔记表现数据
希望分析的时间范围：最近 90 天
最想回答的问题：
  - 哪些选题能稳定带来阅读与涨粉？
  - 哪些笔记曝光高但转化弱？
  - 下一阶段应该增加和减少什么内容？
重点指标：曝光、阅读、点赞、收藏、评论、分享、平均观看时长、涨粉
需要的交付物：Markdown 复盘报告＋可编辑 Excel 分析表
需要隐藏的信息：笔记链接中的个人识别信息
其他限制：自算指标必须写明公式，不把相关性写成因果关系
```

这个任务通常会先完成字段识别与数据质量检查，再按内容主题、表现层级、发布时间和内容类型进行分组，最后输出：

- 高曝光高转化内容；
- 高曝光低转化内容；
- 低曝光高效率的潜力内容；
- 可能失效的内容方向；
- 未来 30 天的测试矩阵；
- 下一批应补充的数据。

## 10. 如何采集自己的数据

只有当你明确提出“帮我搭建采集”时，Skill 才会启动本地采集流程。

最短请求：

```text
使用 business-data-analysis，帮我在本地配置【小红书创作者笔记 / 抖老板订单】数据采集。
数据只保存在本机。请先检查运行环境和本地服务，再告诉我需要在浏览器中完成什么。
```

### 采集流程

```text
检查本机 Node.js
    ↓
启动仅监听 127.0.0.1 的本地服务
    ↓
检查本地健康状态
    ↓
由用户安装 Tampermonkey
    ↓
只导入目标平台对应的用户脚本
    ↓
由用户登录自己的平台账号
    ↓
在有权访问的数据页面采集
    ↓
本地保存 JSON 与 CSV
```

### 用户需要自己完成的动作

- 从浏览器官方扩展商店安装 Tampermonkey；
- 登录自己的小红书或抖老板账号；
- 打开对应的列表或数据页面；
- 确认采集范围只包含自己有权访问的数据；
- 在需要时确认导出或同步。

浏览器扩展安装、平台登录和账号验证默认由用户控制。Skill 不需要、也不会要求你提供密码、Cookie 或访问令牌。

### 本地保存说明

- 本地服务默认只监听 `127.0.0.1`；
- 数据默认保存为 JSON 和 CSV；
- 可以在启动时指定其他输出目录或端口；
- 不会在未经明确要求时把数据上传到第三方。

平台页面、选择器和接口可能变化。如果采集失败，应先检查当前页面结构和数据接口，而不是重复无效点击。

## 12. 数据分析边界

`business-data-analysis` 可以读取你提供的数据、计算指标、识别趋势、生成图表和提出经营建议，但需要遵守以下边界：

- 只采集和分析你自己拥有或获得授权的数据；
- 不要求、记录或展示密码、Cookie、访问令牌；
- 不把数据上传给第三方，除非你明确要求并理解影响；
- 分享报告前，应隐藏不必要的姓名、联系方式、订单号和私密链接；
- 不为缺失金额字段编造收入、GMV、利润或退款口径；
- 不把相关关系直接写成因果关系；
- 样本量不足、日期断层或缺失值严重时，要明确降低结论强度；
- 经营建议是决策辅助，仍需结合业务现场验证。

## 13. 一句话速查

```text
使用 business-data-analysis，分析【平台与数据类型】文件【路径】，回答【核心经营问题】；请先检查行数、日期、缺失、重复、单位和异常，再分析【重点指标与分组】，区分观察与假设，最后交付【报告/表格/图表】、优先行动和下一批应补数据，并隐藏【敏感信息】。
```

先给真实数据，再问具体问题，得到的就不只是一份统计结果，而是一套可以继续验证的经营行动。
